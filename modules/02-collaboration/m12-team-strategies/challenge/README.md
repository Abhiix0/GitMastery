# Challenge — m12

GitHub Flow works great for small teams shipping continuously. But it's not the right fit for every situation.

**The scenario:** You're the tech lead for an 8-person team shipping Stack Overflown as a real product. You have monthly releases and a separate mobile app version. At any given time, two versions of the product are live simultaneously.

GitHub Flow isn't quite right here — you need to maintain two live versions and have a structured release process.

**Your task:** Write a `TEAM_WORKFLOW.md` in the repo root that documents the branching strategy for this team. It should cover:

- Which branches exist permanently and why
- The lifecycle of a feature from start to ship
- What happens when a hotfix is needed on the live version right now
- How releases are prepared and tagged

Write it clearly enough that a new hire could follow it on day one without asking questions.
